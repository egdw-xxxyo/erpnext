# Панель адміністрування: сторінки навігації та локальний режим без SSH

- **Ліва навігація** — панель тепер розбита на 5 сторінок замість однієї великої:
  Dashboard, Backups, Deploy, Configuration, Information. Консоль завдання
  спільна для всіх сторінок.
- **Локальний режим без SSH (`OPS_LOCAL_MODE=1`)** — для машини без запущеного
  sshd (ноутбук розробника). Вхід перевіряє лише `OPS_ALLOWED_USERS`, без
  пароля; команди виконуються прямо в контейнері ops (docker-сокет і
  репозиторій монтуються з хоста через `docker-compose.ops.local.yml`).
  Ніколи не вмикати на спільному чи продовому хості. Деталі:
  `docs/ops-dashboard.md` → «Локальний режим без SSH».
- **Кнопка «Test connection» на панелі FTP backup target** — перевіряє
  з'єднання з поточними значеннями форми (без обов'язкового збереження
  спочатку), показує вміст `remote_dir` як доказ успіху.
- **Виправлено протокол позахостових копій: FTP, а не SFTP.** Ціль передачі
  виявилась звичайним FTP з опортуністичним TLS на порту 21 (підтверджено
  реальним акаунтом Tucha) — попередня реалізація ходила по SFTP/SSH на
  порт 22, який на цьому хості просто не слухає. Жодна реальна передача
  відколи існує ця функція не могла спрацювати; перевірялося лише
  збереження налаштувань. Перейменовано `sftp_config.py`/`sftp.py` →
  `ftp_config.py`/`ftp.py`, `/settings/sftp` → `/settings/ftp` — назви
  тепер відповідають реальності.
- **Виправлено TLS-довіру FTPS-цілі**: сертифікат Tucha не перевіряється
  системним ланцюжком довіри curl (curl 60) — додано `-k` до всіх curl-звернень
  до FTP-цілі.
- **Сторінка Backups перероблена**: інформаційна картка (час останньої
  локальної копії, розклад наступної), кнопка «Create local backup», кнопка
  «Clean old backups» (лишає тільки найновішу копію, з підтвердженням), меню
  з трьох крапок на кожному рядку (Push/Restore/Remove — кожна дія з
  підтвердженням). Секція «Remote backups» тепер показує хост і теку цілі.
  Версія релізу тепер відображається біля IP хоста в шапці на всіх сторінках.
- **Виправлено повільний перехід на /backups**: сторінка більше не чекає
  повний SSH-збір статистики перед рендером — локальні й віддалені бекапи
  вантажаться асинхронно зі своїм станом «завантаження», як усюди інде.
- **Показано статус синхронізації** на локальних копіях: пілюля «synced»,
  якщо копія вже є на віддаленій цілі, «local only» — якщо ні.
- **Багато FTP-цілей замість однієї**: на сторінці Configuration тепер
  таблиця цілей (Add/Edit/Remove), кожна з назвою і позначкою призначення
  (prod/dev/test) — наприклад, dev-інстанс може тримати ціль prod, щоб
  завантажити прод-копію для локального тестування. У розкладі («Push to»)
  тепер обирається конкретна ціль. Сторінка Backups показує всі налаштовані
  цілі окремими картками замість однієї. Стара єдина ціль (`ftp_config.enc`)
  автоматично мігрує в нову таблицю при першому зверненні.
- **`./deploy ops rebuild`** (кнопка «Rebuild dashboard» на Deploy) більше не
  падає з «OPS_SESSION_SECRET is missing a value» — `.ops.env` тепер
  підвантажується самою `ops_dc`, а не лише при старті.
- **Меню з трьох крапок закривається** по кліку поза ним або по вибору дії
  (раніше залишалось відкритим).
