# Виправлення лінтерів CI та двох прихованих помилок

- Увесь код репозиторію приведено до вимог `pre-commit` (prettier, eslint, ruff) — CI-перевірка **Linters** для pull request'ів більше не падає.
- **Виправлено помилку:** функцію `create_variant_bom_from_template` у `bom.py` було визначено двічі. Python залишав лише друге визначення, тож перше (без відновлення прапорця `has_variants`) було мертвим кодом.
- **Виправлено помилку:** метод `before_submit` у **Перевірці якості (Quality Inspection)** також було визначено двічі — через це перевірка `validate_readings_status_mandatory()` ніколи не виконувалась. Обидві перевірки об'єднано в один метод.
- Прибрано зайвий запит до бази (`posting_date`) під час генерації серійних номерів у `serial_batch_bundle.py`.
- Додано відсутні імпорти дочірніх DocType у блоках `TYPE_CHECKING` (**Робоче місце (Workplace)**, **Сканер (Scanner)**).
- Налаштування `ruff`: `frappe` позначено як сторонній пакет (інакше через submodule `frappe/` переписувались імпорти в усіх файлах), а перевірки `RUF002`/`RUF003` вимкнено, бо українські коментарі й docstring'и містять кирилицю.
- У `CLAUDE.md` додано розділ про обов'язковий запуск `pre-commit` перед комітом.
