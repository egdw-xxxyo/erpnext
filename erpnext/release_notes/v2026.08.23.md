# Види відпусток у табелі та автоматичний прогрес завдання

## Табель відвідуваності: оплачувана відпустка й відпустка за власний рахунок

У табелі будь-яка відпустка виглядала однаково — позначкою **ВП**, — тому відпустку за власний
рахунок не можна було відрізнити від оплачуваної, не відкриваючи саму заяву.

Тепер на картці типу відпустки з'явилося поле **Позначка в табелі** (до 5 символів). Воно
показується в клітинці другим рядком, під позначкою стану — там само, де показуються години
переробітку й недоробітку.

- наявним типам позначки проставлені автоматично: відпустка без збереження заробітної плати
  отримала **ЗаВл**, решта — **Офіц**;
- новий тип відпустки отримує свою позначку на власній картці, без змін у коді;
- тип без позначки показується в табелі як відпустка загалом, тобто **ВП**, як і раніше;
- підказка клітинки тепер показує стан, години, зміну й ознаку погодження одним рядком.

У зведеному виді заголовки колонок вирівняні між собою.

## Прогрес завдання більше не редагується вручну

Поле **% Прогрес** у завданні перестало бути полем для ручного введення. Тепер це показник, який
система розраховує сама, і поведінка залежить від типу завдання.

### Звичайне завдання: прогрес визначає статус

Значення жорстко прив'язане до статусу і приймає лише два стани:

| Статус | % Прогрес |
|---|---|
| **Завершено** | 100% |
| будь-який інший (Нове, В роботі, Очікує інформації, Заблоковано, На перевірці, **Скасовано**) | 0% |

Раніше прогрес вводився руками, а система лише піднімала його до 100% при переведенні у
**Завершено** — і назад він уже не опускався, навіть якщо завдання повертали в роботу. Тепер
значення перераховується при кожному збереженні в обидва боки: повернули завдання зі статусу
**Завершено** у **В роботі** — прогрес одразу стає 0%.

### Групове завдання: без змін

Групове завдання (галочка **Група**) як рахувало прогрес за своїми дочірніми завданнями, так і
рахує: `завершені / (усього − скасовані) × 100`.

### Поле заблоковане для всіх завдань

Раніше редагування було закрите лише для групових завдань. Тепер поле **% Прогрес** доступне
тільки для читання в усіх завданнях, і сервер перезаписує будь-яке передане значення — через
форму, список, API чи імпорт даних.

### Що варто знати

- **Наявні дані.** Завдання, у яких зараз стоїть проміжний прогрес (наприклад 42%), показуватимуть
  його доти, доки їх не збережуть наступного разу. Масового перерахунку наявних завдань не
  виконується.
- **Відсоток виконання проєкту.** Якщо у проєкті обрано метод розрахунку **Task Progress** або
  **Task Weight**, він підсумовує прогрес завдань. Оскільки прогрес звичайного завдання тепер лише
  0 або 100, ці методи фактично рахують частку завершених завдань.
